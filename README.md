# kikobot-lerobot

Kiko-Bot is a 6-DOF desktop robot arm built from Feetech STS servos, with a
two-finger gripper. This repository is its [LeRobot](https://github.com/huggingface/lerobot)
plugin. The same commands and the same gamepad drive three versions of the arm:
- a MuJoCo simulation;
- an NVIDIA Isaac Sim simulation;
- the real arm.

That makes it possible to teleoperate, record datasets, generate scripted
demonstrations and train policies in simulation, then run them on the
hardware.

| LeRobot type | What it is |
|---|---|
| `--robot.type=kikobot_sim` | The arm in `kikobot-sim-server` (MuJoCo, optionally Newton physics on a GPU) |
| `--robot.type=kikobot_isaac` | The arm in the Isaac Sim server (Newton physics, RTX camera) |
| `--robot.type=kikobot_follower` | The real arm, its servo bus opened by LeRobot, mirrored into a sim |
| `--robot.type=kikobot_arm` | The real arm through `kikobot-arm-server`, so several programs can reach it at once |
| `--teleop.type=kikobot_gamepad` | Xbox / PlayStation gamepad: full 6-DOF control of the gripper |

All of them share one action space: `J1.pos` to `J6.pos` in degrees, and
`gripper.pos` in % open. A dataset recorded on one, or a policy trained on
it, runs on the others.

The simulated scene is a study desk with a hutch and a tube light, in a room
lit by eight downlights. The arm stands in the desk's front-left corner,
next to a stationery sorting station: cups, a tape peg and trays, plus
real-sized pens, pencils, markers, tape rolls and other supplies to tidy
into them. One camera watches the arm and the items. See [docs/sim.md](docs/sim.md).

## Install

You need Python 3.12+, git, and LeRobot installed from source. LeRobot,
MuJoCo and this plugin go into **one** virtual environment.

**Ubuntu 22.04 / 24.04** (on 22.04, get Python 3.12 from the deadsnakes PPA)

```bash
sudo apt install -y git python3.12-venv libgl1 libglfw3
sudo usermod -aG dialout $USER            # serial port access; log out and back in

git clone https://github.com/huggingface/lerobot.git ~/lerobot
cd ~/lerobot
python3.12 -m venv .venv
.venv/bin/pip install -e ".[core_scripts,training,feetech]"

git clone https://github.com/SanchakGarg/kikobot-lerobot.git ~/kikobot-lerobot
cd ~/kikobot-lerobot
~/lerobot/.venv/bin/pip install -e .

# Optional: a stable /dev/kikobot name and 1 ms FTDI latency. Replug the adapter after.
sudo cp udev/99-kikobot.rules /etc/udev/rules.d/
sudo udevadm control --reload-rules && sudo udevadm trigger
```

**Windows 10 / 11 (PowerShell).** Install Python 3.12 from python.org first
(tick "Add python.exe to PATH"), and Git for Windows.

```powershell
git clone https://github.com/huggingface/lerobot.git $HOME\lerobot
cd $HOME\lerobot
py -3.12 -m venv .venv
# NVIDIA GPU only: install CUDA torch first, or pip picks the CPU build.
.venv\Scripts\pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
.venv\Scripts\pip install -e ".[core_scripts,training,feetech]"

git clone https://github.com/SanchakGarg/kikobot-lerobot.git $HOME\kikobot-lerobot
cd $HOME\kikobot-lerobot
& "$HOME\lerobot\.venv\Scripts\pip.exe" install -e .
```

The servo adapter needs its USB-serial driver:
- CH340/CH343 adapters (Feetech URT-1, Waveshare): from the WCH website.
- FTDI adapters: from ftdichip.com. Then set Device Manager → the port →
  Port Settings → Advanced → Latency Timer to 1 ms.

**macOS:** the same as Ubuntu, without `apt`, `dialout` and udev.

From here on, `$V` is the venv's scripts folder:
- Ubuntu and macOS: `V=~/lerobot/.venv/bin`.
- Windows: `$V="$HOME\lerobot\.venv\Scripts"`. Run tools as
  `& "$V\lerobot-teleoperate.exe"`, and continue lines with a backtick
  instead of `\`.

**Check the plugin loaded.** If the plugin fails to import, LeRobot only
logs the error, and the types are silently missing:

```bash
$V/python -c "
from lerobot.utils.import_utils import register_third_party_plugins
from lerobot.robots import RobotConfig
register_third_party_plugins()
print(sorted(c for c in RobotConfig.get_known_choices() if 'kikobot' in c))"
```

It must print `['kikobot_arm', 'kikobot_follower', 'kikobot_isaac', 'kikobot_sim']`.

## Quick start: the sim

This needs no hardware. Plug the gamepad in before starting teleop: it is
only detected at startup.

```bash
# Terminal 1: the sim server. Leave it running.
$V/kikobot-sim-server --scene desk_sort
# On macOS, MuJoCo's window needs mjpython:
#   $V/mjpython -m lerobot_robot_kikobot.sim_server --scene desk_sort

# Terminal 2: drive it with the gamepad.
$V/lerobot-teleoperate --robot.type=kikobot_sim --teleop.type=kikobot_gamepad --fps=60
```

Add `--display_data=true` to the teleop command to see the camera and the
joints in rerun. Other scenes are `pick_place`, `cylinder` and `empty`.
Server options, the room and the desk are in [docs/sim.md](docs/sim.md).

## Run the real arm

Before you start:
- Power the servo bus (12 V) and plug in its USB adapter.
- Plug in or pair the gamepad.
- Leave the arm clear: on connect it eases to its home pose.

Run from a desktop session, not bare SSH, because the gamepad is read
through GLFW. The port is `/dev/ttyACM0`, `/dev/kikobot` (with the udev
rule) or `COM3` on Windows; `$V/lerobot-find-port` finds it.

```bash
# 1. Try it in the sim first (see above), then calibrate the real arm once.
#    Support the arm: each joint goes limp while you move it to its ends.
$V/lerobot-calibrate --robot.type=kikobot_follower --robot.port=/dev/ttyACM0 --robot.id=kikobot

# 2. Optional: start the sim server, so the sim arm mirrors the real one.
$V/kikobot-sim-server

# 3. Drive it.
$V/lerobot-teleoperate --robot.type=kikobot_follower --robot.port=/dev/ttyACM0 \
  --robot.id=kikobot --teleop.type=kikobot_gamepad --fps=60
```

**Through the arm server.** To watch and set the servos' current and torque
limits while you drive, run the arm as its own server instead of step 3,
with one terminal each:

```bash
$V/kikobot-arm-server --robot.port=/dev/ttyACM0 --robot.id=kikobot     # holds the bus; leave it running
$V/lerobot-teleoperate --robot.type=kikobot_arm --teleop.type=kikobot_gamepad \
  --teleop.robot_id=kikobot --fps=60
$V/kikobot-servo-web                                                    # http://127.0.0.1:8080
```

On a Raspberry Pi with the Waveshare Bus Servo Driver HAT, use
`--robot.port=/dev/serial0`. To drive the arm from a laptop, add
`--host=0.0.0.0` to the arm server and `--robot.host=<Pi's IP>` to the
teleop command.

Ctrl+C stops teleop. Torque stays on so the arm does not drop.

The calibration walkthrough, home pose, joint directions, sag correction,
all follower options, the servo limits, the Pi setup and tuning are in
[docs/real-arm.md](docs/real-arm.md).

## Gamepad controls

Xbox layout. On PlayStation: cross = A, circle = B, square = X, triangle = Y.

| Control | Action |
|---|---|
| Left stick | Move forward / back / left / right |
| LT / RT | Move down / up |
| Right stick ← → / ↑ ↓ | Roll / pitch the jaws |
| LB / RB | Yaw the jaws |
| A / B (hold) | Close / open the jaws |
| X | Precision mode on/off (30 % speed) |
| Y | Glide back to the home pose |
| Back / View / Share | Sims only: reset the scene (a new desk) |

Moves are in the arm's base frame, and rotations are about the jaws' own
axes. At the edge of the reach, or at a joint limit, the arm stops.

Options are set with `--teleop.<name>=`:
- `linear_speed_m_s`: 0.12
- `angular_speed_deg_s`: 90
- `gripper_speed_pct_s`: 120
- `deadzone`: 0.12
- `input_smoothing_s`: 0.12
- `stop_rate_per_s`: 4
- `precision_scale`: 0.3
- `joystick`: 0
- `robot_id`: `kikobot`, whose saved home pose to use

## Record datasets

**With the gamepad.** LeRobot's recorder works with every robot type:

```bash
$V/lerobot-record --robot.type=kikobot_sim --teleop.type=kikobot_gamepad \
  --dataset.repo_id=local/kikobot_sim --dataset.root=datasets/kikobot_sim \
  --dataset.single_task="Put the pen in the pen cup" \
  --dataset.num_episodes=20 --dataset.push_to_hub=false
```

- **On the real arm:** use `--robot.type=kikobot_follower` with its port and
  id, and add a camera with `--robot.cameras`
  ([docs/real-arm.md](docs/real-arm.md#6-recording-on-the-real-arm)).
- **In the sims:** press Back on the gamepad between episodes to reset the
  scene.

**Without a human.** `kikobot-datagen` has a scripted expert tidy the desk,
one kind of item into its station per episode:
- It keeps only episodes that pass every check.
- It exports them as RLDS datasets for fine-tuning OpenVLA.
- On a cluster, this runs as three `sbatch` jobs.

```bash
$V/kikobot-datagen record --task pen --episodes 3 --out datasets/kikobot_desk --engine mujoco --renderer opengl
$V/kikobot-datagen preview --task pen --out datasets/kikobot_desk --episode 0
```

The tasks, the checks, the dataset layout and the cluster jobs are in
[docs/datagen-openvla.md](docs/datagen-openvla.md).

## Isaac Sim and training on a cluster

- **Isaac Sim.** The Isaac Sim server runs in Isaac Sim's own Python and
  builds the same room and desk. Start with
  [setup](docs/isaac-sim-setup.md), then [teleop](docs/isaac-sim-teleop.md).
- **Training.** Record in a sim, train on a SLURM GPU cluster, and run the
  policy in the sim or on the real arm:
  [record, train, evaluate](docs/isaac-sim-record-and-train.md) and
  [SLURM training](docs/slurm-training.md).

## Tests

```bash
$V/pip install pytest && $V/python -m pytest
```

No hardware or Isaac Sim is needed. The USD tests run when `usd-core` is
installed, and the Newton and RLDS tests when their extras are.
